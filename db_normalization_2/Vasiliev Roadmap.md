# Система управления арендной недвижимостью

## О проекте

Данный проект представляет собой информационную систему для управления арендной недвижимостью. Основная цель проекта — автоматизировать процессы хранения информации о клиентах, объектах недвижимости, заселениях и платежах.

---

# Цель проекта

Разработать структуру базы данных, позволяющую:

- хранить сведения о клиентах;
- учитывать объекты недвижимости;
- регистрировать заселения;
- вести историю платежей;
- обеспечить целостность данных с помощью ограничений и связей.

---

# Roadmap проекта

## Этап 1. Анализ предметной области

На первом этапе была изучена предметная область управления арендной недвижимостью.

Были определены основные бизнес-процессы:

- регистрация клиентов;
- добавление объектов недвижимости;
- оформление заселения;
- учет оплаты аренды;
- хранение истории аренды.

---

## Этап 2. Проектирование базы данных

После анализа предметной области были выделены основные сущности системы.

### Сущности

- Client
- Property
- Settlement
- Payment

Для каждой сущности были определены атрибуты, типы данных и ограничения.

---

## Этап 3. Создание структуры таблиц

### Clients

Хранит информацию о клиентах.

| Поле | Тип | Описание |
|------|-----|----------|
| ClientID | INTEGER | Первичный ключ |
| FirstName | VARCHAR(50) | Имя |
| LastName | VARCHAR(50) | Фамилия |
| Patronymic | VARCHAR(50) | Отчество |
| PassportNumber | VARCHAR(20) | Номер паспорта |
| Phone | VARCHAR(20) | Телефон |

### Ограничения

- PRIMARY KEY(ClientID)
- UNIQUE(PassportNumber)

---

### Properties

Хранит сведения об объектах недвижимости.

| Поле | Тип |
|------|-----|
| PropertyID | INTEGER |
| Address | VARCHAR(255) |
| Rooms | INTEGER |
| MonthlyRent | NUMERIC(10,2) |
| Status | VARCHAR(20) |

### Ограничения

- PRIMARY KEY(PropertyID)
- Rooms > 0
- MonthlyRent > 0
- Status ∈ {Available, Occupied, Repair}

---

### Settlements

Хранит информацию о заселениях.

| Поле | Тип |
|------|-----|
| SettlementID | INTEGER |
| ClientID | INTEGER |
| PropertyID | INTEGER |
| CheckInDate | DATE |
| CheckOutDate | DATE |
| RentalCost | NUMERIC(10,2) |

### Ограничения

- PRIMARY KEY(SettlementID)
- FOREIGN KEY(ClientID)
- FOREIGN KEY(PropertyID)
- CheckOutDate > CheckInDate
- RentalCost > 0

---

### Payments

Хранит информацию об оплате аренды.

| Поле | Тип |
|------|-----|
| PaymentID | INTEGER |
| SettlementID | INTEGER |
| Amount | NUMERIC(10,2) |
| PaymentDate | DATE |
| PaymentMethod | VARCHAR(30) |

### Ограничения

- PRIMARY KEY(PaymentID)
- FOREIGN KEY(SettlementID)
- Amount > 0

---

# Связи между таблицами

```
Один клиент → много заселений
```

---

## Properties → Settlements

Тип связи:

```

```

---

## Settlements → Payments

Тип связи:

```
Одно заселение → множество платежей
```

# Контроль целостности данных

В базе данных используются следующие механизмы контроля:

- PRIMARY KEY;
- FOREIGN KEY;
- UNIQUE;
- CHECK;
- NOT NULL.

Это предотвращает появление некорректных данных и обеспечивает корректную работу системы.
